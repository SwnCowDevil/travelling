# 灰狐 Loading 动画接入设计

## 目标

使用用户提供的 `miniprogram_loading_gray_fox_192_v3.gif` 统一小程序中的页面级等待反馈，让一键推荐、攻略生成及收藏页面加载过程具有一致的品牌感，同时避免影响按钮尺寸和现有交互。

## 资源策略

- 将 GIF 复制到小程序本地资源目录 `miniprogram/miniprogram/assets/images/loading-gray-fox.gif`。
- 资源随小程序代码包发布，不依赖网络地址或后端服务。
- 原图为 192×192、约 43KB，不进行重新编码，避免破坏 GIF 动画。

## 组件设计

扩展现有 `components/loading-stage`，使其成为统一的页面级 Loading 组件：

- 显示灰狐 GIF、阶段文案和轻微淡入动画。
- 默认 GIF 尺寸约 `160rpx`，收藏页可通过组件属性使用紧凑尺寸。
- 文案由调用页面传入；图片异常时文字仍可正常展示。
- 组件不创建全屏遮罩，也不主动阻止页面滚动或操作；是否禁用重复提交仍由页面现有状态控制。

## 使用范围

### 一键推荐

- 保留按钮内简短的“正在推荐”状态。
- 推荐请求进行时，在推荐结果区域使用灰狐组件展示已有的动态阶段文案。
- 保留现有骨架卡片，作为即将出现推荐结果的结构提示。

### 目的地详情与攻略生成

- 目的地详情首次加载时，以灰狐组件替换仅有骨架块的等待反馈，并可保留轻量骨架背景。
- 快速生成或深度生成期间，在攻略生成卡片内显示灰狐动画和对应生成文案。
- 生成期间保留已展示的旧攻略，不使用全屏遮罩；失败时仍沿用现有错误提示和旧内容保留逻辑。

### 收藏攻略

- 收藏列表和收藏详情首次加载时，以紧凑版灰狐组件替换“正在加载…”纯文字。
- 空列表、加载错误和编辑状态不显示 GIF，继续使用各自的明确文案。

### 不接入的场景

以下短时按钮操作继续使用 Vant 或微信原生小型 Loading：

- 收藏保存、攻略编辑保存与删除。
- 自定义目的地搜索。
- AI 配置测试并保存。

这样可避免 192×192 GIF 改变按钮高度或造成界面跳动。

## 数据与状态流

页面继续使用现有 `loading`、`regenerating` 等布尔状态。组件只负责展示，不负责发起请求或修改业务状态：

1. 页面发起请求并设置 Loading 状态。
2. WXML 根据状态渲染 `loading-stage`，传入当前阶段文案和尺寸。
3. 请求成功或失败后，页面清除状态，组件随条件渲染自动移除。

不新增后端接口、数据库字段或全局状态。

## 错误处理

- GIF 是本地静态资源，加载失败不会阻断请求。
- Loading 文案始终与 GIF 分离渲染，因此资源异常时仍有可理解的反馈。
- API 错误继续进入各页面现有的 `catch` 分支，不改变错误提示规则。

## 测试

- 验证 GIF 资源存在并保持 GIF 文件格式。
- 验证统一组件引用本地灰狐资源，并支持默认/紧凑尺寸与文案。
- 验证推荐、目的地详情、收藏列表和收藏详情在页面级等待状态使用统一组件。
- 验证保存、搜索和 AI 设置等按钮仍使用原有小型 Loading。
- 运行完整小程序测试，确认现有推荐、攻略、收藏与足迹行为不受影响。

## 非目标

- 不修改 GIF 内容、颜色或动画帧。
- 不为所有异步请求增加全局遮罩。
- 不修改后端 API 或请求超时。
