# 微信小程序正式凭据配置设计

## 目标

为旅行推荐微信小程序启用正式微信登录，并保证微信 AppSecret 不进入小程序包、Git 历史、设计文档或日志。

## 当前状态

- 小程序工程的 AppID 已配置，无需修改前端业务代码。
- FastAPI 已支持通过 `TRAVEL_WECHAT_APP_ID` 和 `TRAVEL_WECHAT_APP_SECRET` 读取微信凭据。
- 本地 `backend/.env` 已被 Git 忽略，服务器通过 `/etc/travelling/travel-api.env` 向容器提供私密环境变量。
- 正式版和体验版使用 `https://api.sunks.cc`，开发版继续使用本地后端。

## 方案

### 本地配置

在 `backend/.env` 中写入 AppID 和 AppSecret。本文件不提交 Git。修改后检查配置是否能被 FastAPI 读取，但测试和日志只输出“已配置”及长度，不输出真实值。

### 服务器配置

在 ECS 的 `/etc/travelling/travel-api.env` 写入相同的两个变量，保持文件仅管理员可读。执行现有 `/opt/travelling/scripts/restart-backend.sh`，让容器重新读取环境变量。

### 安全边界

- AppID 可以保存在小程序工程配置中。
- AppSecret 只能保存在本地后端 `.env` 与服务器私密环境文件中。
- AppSecret 不得出现在 WXML、JavaScript、项目配置、Git 提交、测试快照、部署脚本参数或日志中。
- 当前密钥已通过对话传递。完成首次连通验证后，应在微信公众平台重置密钥，再只更新两个私密环境文件。

## 验证

1. 确认本地 Settings 能读取两个变量，且不打印原值。
2. 运行后端认证与配置测试。
3. 重启服务器容器并检查 `http://127.0.0.1:8000/health`。
4. ICP 备案通过且合法域名配置完成后，用体验版执行 `wx.login`，确认 `/auth/wechat` 返回登录令牌。
5. 真机回归定位、推荐、AI 攻略、足迹和收藏。

## 上线待办

1. 等待 `sunks.cc` ICP 备案通过。
2. 确认 `api.sunks.cc` 的 DNS、HTTPS 证书和公网健康检查正常。
3. 在微信公众平台配置 `https://api.sunks.cc` 为 request 合法域名。
4. 完成小程序备案、服务类目、隐私保护指引、位置权限用途与用户协议配置。
5. 对 AI 生成内容补充显著标识、内容安全措施和适用的生成式 AI/算法合规材料。
6. 上传体验版并完成真机验收，然后提交微信审核。
7. 服务正式开通后，在法定期限内办理公安联网备案，并在对应页面展示备案编号。

## 失败处理

- 微信接口失败时，后端返回通用错误，不向前端暴露 AppSecret 或微信原始敏感响应。
- 密钥重置后登录失败时，优先检查服务器环境文件是否同步以及容器是否重启。
- ICP 尚未通过或合法域名尚未生效时，不把域名网络失败误判为微信密钥错误。
