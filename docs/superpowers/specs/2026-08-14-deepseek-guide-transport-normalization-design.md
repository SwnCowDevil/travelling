# DeepSeek 攻略交通字段兼容设计

## 背景

DeepSeek 官方接口会偶发把每日行程的 `transport` 返回为字符串数组、把美食人均价格返回为数字，并在深度模式中把推荐亮点返回为包含名称和理由的对象数组，而当前响应模型只接受对应的字符串。上游请求成功后，Pydantic 因类型不匹配拒绝整份攻略，详情页最终只显示统一的 AI 生成失败提示。

## 设计

- 在 `ItineraryDay` 的输入边界兼容非空字符串数组，将其清理后用中文分号合并为单个字符串。
- 空数组、混有非字符串或空字符串的数组继续校验失败，避免掩盖无效 AI 数据。
- 在 `FoodRecommendation` 的输入边界把非负有限数字转换为带单位的价格字符串；其他无效类型仍然拒绝。
- 在 `GuidePayload` 的输入边界把具备有效名称和推荐理由的亮点对象合并成“名称：理由”字符串；字段缺失或类型无效的对象仍然拒绝。
- 快速和深度攻略提示词都明确规定每日行程的 `theme`、`morning`、`afternoon`、`evening`、`transport`、`caution` 必须是字符串，减少触发兼容逻辑的概率。
- 提示词明确列出不得遗漏的顶层字段，并要求 `average_price` 为带货币单位的字符串。
- 提示词明确要求亮点使用单个字符串，不得返回对象。
- 顶层 `transport` 仍保持字符串数组，不改变现有 API 响应结构、缓存结构或前端渲染协议。

## 验证

- 新增回归测试，证明字符串数组会规范化为字符串。
- 新增回归测试，证明数字价格会规范化为带单位的字符串。
- 新增回归测试，证明深度模式的亮点对象会规范化为字符串。
- 新增提示词约束测试，覆盖快速和深度模式。
- 运行攻略相关测试以及后端完整测试。
