# 推荐距离区间筛选设计

## 目标

在旅行推荐页加入“距离所在地区”的固定区间筛选，让用户按出发地与目的地之间的直线距离限定推荐范围。

## 用户界面

距离筛选位于推荐页“更多”面板中，标题为“距离所在地区”，使用单选标签：

- 不限（默认）
- <100km
- 100–200km
- 200–300km
- 300–400km
- 400–500km
- >500km

选中任一距离区间后：

- “更多”入口计数包含该筛选。
- 筛选摘要新增距离标签，可通过关闭按钮单独清除。
- 点击“重置”恢复为“不限”。
- 自定义目的地搜索、按钮 Loading 和其他筛选项不受影响。

不新增顶部筛选入口，避免现有五个入口在窄屏设备上拥挤。

## 距离边界

新距离区间采用左闭右开规则，防止边界目的地同时落入两个选项：

| 选项 | 最小距离 | 最大距离 | 包含关系 |
| --- | ---: | ---: | --- |
| 不限 | 无 | 无 | 全部 |
| <100km | 0 | 100 | `[0, 100)` |
| 100–200km | 100 | 200 | `[100, 200)` |
| 200–300km | 200 | 300 | `[200, 300)` |
| 300–400km | 300 | 400 | `[300, 400)` |
| 400–500km | 400 | 500 | `[400, 500)` |
| >500km | 500 | 无 | `[500, +∞)` |

距离继续使用当前的 Haversine 直线距离计算；不表示驾车、铁路或步行距离。

## 前端数据流

推荐页筛选状态新增 `distanceRange`，其值为 `null` 或固定区间标识。前端模型维护区间标识与 `min_distance_km`、`max_distance_km` 参数的映射：

- `null` 不发送距离参数。
- 其他值同时或按需发送 `min_distance_km` 与 `max_distance_km`。

请求继续发送至 `POST /recommendations`，并继承当前出发地、月份、偏好、季节和人流等筛选条件。

## 后端接口与过滤

`RecommendationCreate` 新增可选 `min_distance_km`，允许 `0` 及正数。`max_distance_km` 保持现有可选字段和兼容语义。

候选过滤规则：

- 新增最小距离时，距离小于该值的候选被排除。
- 当最小距离与最大距离同时存在时，距离大于或等于最大值的候选被排除，实现左闭右开区间。
- 仅使用旧的最大距离参数时，保留原有“距离大于最大值才排除”的兼容行为。
- 任何距离条件下，没有已校准坐标的候选都不参与结果。

## 错误处理

- 后端拒绝负数最小距离、非正最大距离以及最小距离大于等于最大距离的请求。
- “不限”不传距离参数，因此不会因为距离筛选导致空结果。
- 候选不足时继续沿用现有策略，不放宽用户已选择的距离条件。

## 测试

- 前端：默认、不限、各个区间到请求参数的映射；单选切换、摘要、移除与重置。
- 后端：Schema 边界验证；每个边界的下限包含、上限排除；旧最大距离参数兼容。
- API：区间请求只返回指定范围的推荐结果。
- 运行完整后端和小程序测试。

## 非目标

- 不提供自定义公里数输入或滑杆。
- 不改为路线距离。
- 不改变推荐排序、AI 调用或缓存策略。
