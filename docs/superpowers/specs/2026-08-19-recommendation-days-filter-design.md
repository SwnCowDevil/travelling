# 推荐页游玩天数筛选设计

## 目标

恢复推荐页“游玩天数”选择，让一键推荐和主动输入目的地都继承用户选择；用户不选择时，攻略继续默认生成 2 天。

## 交互

- 在“更多”筛选中增加“游玩天数”，提供 `1天 / 2天 / 3天 / 5天 / 7天` 快捷选项。
- 天数为单选；再次点击已选天数可取消选择。
- 未选择时不限制一键推荐的可用天数，进入攻略详情时默认使用 2 天。
- 已选择的天数出现在筛选摘要中，并计入“更多”的已选数量；可从摘要删除，也可通过重置清除。

## 数据流

- `filters.days` 保持 `number | null`。
- 选择天数后，推荐请求使用现有 `available_days` 字段。
- 主动输入目的地和普通推荐卡片进入详情时都传递 `filters.days || 2`。
- 后端协议不变。

## 验证

- 模型测试覆盖天数选项、单选/取消、摘要、重置和请求映射。
- 页面行为测试覆盖普通推荐卡片进入详情时传递已选天数及默认 2 天。
- 静态视图测试确认“游玩天数”控件存在。
- 运行小程序完整测试。
